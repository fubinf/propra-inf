[SECTION::goal::trial]
Ich kann mit `sudo apt install` ein Programm auf meinem Debian-System installieren.
[ENDSECTION]


[SECTION::background::default]
Ein Linux-System besteht aus _Paketen_.
Ein Paket enthält ein Programm (oder eine Bibliothek) samt allem, was dazugehört.

Pakete installiert ein _Paketmanager_:
Er lädt das Paket herunter und installiert es mit allen notwendigen Abhängigkeiten.
Auf Debian-basierten Systemen heißt der Paketmanager [TERMREF::apt].

Die Dateien eines Pakets landen in Systemverzeichnissen,
damit alle Benutzer eines Systems das Programm verwenden können.
In diese Verzeichnisse darf nur der Administrator-Benutzer `root` schreiben.
Deshalb brauchen Sie zum Installieren Administratorrechte, die Sie mit dem Werkzeug `sudo` bekommen.
[ENDSECTION]


[SECTION::instructions::detailed]

[NOTICE]
Auf einem **Poolrechner** der Uni haben Sie keine Administratorrechte.
Falls Sie auf einem Poolrechner arbeiten, könnten Sie diese Aufgabe im Prinzip überspringen,
weil Sie die Aufgaben, in denen `apt` benötigt wird, sowieso nicht bearbeiten können,
falls das betreffende Paket nicht ohnehin schon installiert ist.  
Die aktuelle Aufgabe zu _lesen_ lohnt sich aus Gründen der Allgemeinbildung aber trotzdem.
[ENDNOTICE]

[NOTICE]
Auf dem **Mac** gibt es kein `apt`.
Dort übernimmt `brew` diese Rolle, und zwar ohne `sudo` (siehe [PARTREF::CLI-MacOS-brew]).
Fall Sie auf einem Mac arbeiten, können Sie die `apt`-haltigen Aufgaben _überwiegend_ auch bearbeiten,
müssen aber selbständig die jeweiligen `apt`-Kommandos in passende `brew`-Kommandos
umsetzen.
Diese Aufgabe erklärt nochmals ungefähr, wie das geht.
Die Teile zu `sudo` sind für Sie nicht direkt relevant, aber zur Allgemeinbildung trotzdem
zum Lesen empfohlen.
Als Mac-Benutzer werden Sie erst im letzten Abschnitt aktiv, davor bitte einfach nur mitlesen.
[ENDNOTICE]

**Wer schon weiß**, was `sudo` tut, und Pakete mit `apt` installieren kann,
lernt hier nichts Neues, denn diese Aufgabe behandelt nur Grundwissen;
Sie sollten diese Aufgabe dann überspringen.
Eine vertiefende `apt`-Aufgabe gibt es weiter hinten im ProPra. 

### Was `sudo` tut

Für die meisten ProPra-Aufgaben genügt Folgendes Wissen über [TERMREF::sudo]:

- `sudo` steht vor einem Kommando, beispielsweise `sudo apt install jq`.
  Das bedeutet das Gleiche wie `apt install jq`, außer, dass das Kommando
  mit Adminstratorrechten ausgeführt wird statt mit Ihren normalen Benutzerrechten.
- `sudo` fragt nach _Ihrem_ Passwort, nicht nach dem von `root`.
- Während Sie das Passwort tippen, erscheint _nichts_ auf dem Bildschirm.

[WARNING]
Mit Administratorrechten kann man das System sehr schnell übel beschädigen,
wenn man sich beim Kommando vertut.
Setzen Sie `sudo` deshalb nur vor Kommandos, bei denen Sie wissen, was sie tun
(oder ausnahmsweise im ProPra: wenn eine Aufgabe es ausdrücklich verlangt) 
und wo `sudo` auch wirklich nötig ist.
[ENDWARNING]


### Versuch 1 (klappt nicht): Paket installieren ohne `sudo`

Als Beispiel nehmen wir das Paket `jq`, das noch nicht installiert ist.
Es verarbeitet Daten im JSON-Format.

[EC] Versuchen Sie, `jq` zu installieren:  
`apt install jq`

Lesen Sie die Fehlermeldung.
Sie endet mit der Frage `are you root?` (bei deutscher Spracheinstellung: `sind Sie root?`).

[EC] Die Fehlermeldung nennt eine Datei, die `apt` nicht öffnen konnte.
Sehen Sie sich diese Datei mit `ls -l DATEINAME` genauer an.

Die Ausgabe sieht ungefähr so aus:

```
-rw-r----- 1 root root 0 Jul  9 14:41 /var/lib/dpkg/lock-frontend
```

So lesen Sie sie:

- Das erste `root` ist der Eigentümer der Datei, das zweite die Gruppe, der die Datei gehört.
- `-rw-r-----` am Anfang sind die Zugriffsrechte.
  Das erste Zeichen (`-`) sagt nur, dass es eine gewöhnliche Datei ist.
  Danach folgen drei Dreiergruppen:  
  `rw-` für den Eigentümer (Rechte für lesen (read) und schreiben (write)),  
  `r--` für die Gruppe (nur read),  
  `---` für alle anderen (gar nichts).

Sie sind weder `root` noch in der Gruppe `root`, gehören also zu "alle anderen"
und dürfen die Datei nicht einmal lesen, geschweige denn schreiben.
Ohne `sudo` läuft `apt` mit Ihren Rechten und scheitert genau daran (`Permission denied` bzw. `Keine Berechtigung`).
Ebenso wenig dürfte es die Programmdateien in Systemverzeichnisse wie `/usr/bin` schreiben,
was ein Hauptzweck von `apt install` ist.
Mit `sudo` läuft `apt` dagegen mit den Rechten von `root` und darf all das.


### Vorbereitungsschritt: Paketkatalog aktualisieren

`apt` arbeitet mit einem Katalog aller verfügbaren Pakete, der auf Ihrem System gespeichert ist.
`apt update` lädt die neueste Fassung dieses Katalogs herunter, installiert aber noch nichts.
Ist der Katalog veraltet, kennt `apt` neuere Pakete nicht oder versucht, überholte
Paketversionen herunterzuladen, und scheitert daran.
Deshalb ruft man `apt update` vor `apt install` auf.

[EC] Aktualisieren Sie den Paketkatalog:  
`sudo apt update`

Geben Sie Ihr Passwort ein, wenn Sie danach gefragt werden.
Das Passwort bleibt ein paar Minuten lang gültig; Sie werden also nicht unbedingt
jedes Mal gefragt.

[HINT::`sudo` fehlt oder meldet, ich sei nicht in der sudoers-Datei]
Das passiert, wenn bei der Installation von Debian ein Passwort für `root` vergeben wurde:
Dann richtet der Installer `sudo` für Ihren Benutzer nicht ein.
Holen Sie das als `root` nach:

- `su -` macht Sie zu `root` und fragt dafür nach dem Passwort von `root`.
- Nur falls es `sudo` gar nicht gibt (`command not found`): `apt install sudo`.
- `adduser IHRNAME sudo` nimmt Sie in die Gruppe `sudo` auf.
- `exit` beendet die Shell von `root`.

Melden Sie sich danach ab und wieder an, damit die neue Gruppenzugehörigkeit gilt.
[ENDHINT]


### Versuch 2: Paket installieren

`jq` braucht weitere Pakete (Bibliotheken), die `apt` gleich mitinstalliert.
Deshalb fragt `apt` mit `[Y/n]` (bzw. `[J/n]`) nach.
Lesen Sie die angezeigte Paketliste, bevor Sie bestätigen:
Sollen dabei Pakete entfernt werden, ist Ihr System in einem ungewöhnlichen Zustand;
brechen Sie die Installation dann vorsichtshalber mit `n` ab.

[EC] Installieren Sie jetzt `jq`, diesmal mit `sudo`:  
`sudo apt install jq`

[EC] Prüfen Sie, ob das neue Programm funktioniert.
Viele Programme geben mit der Option `--version` ihre Versionsnummer aus:  
`jq --version`


### Und wie geht das auf dem Mac?

Auf macOS gibt es kein `apt`.
Die meisten Mac-Benutzer_innen, die etwas Entsprechendes brauchen,
benutzen stattdessen _Homebrew_: 
[HREF::https://brew.sh/]

Probieren Sie, ob das Kommando `brew` bei Ihnen existiert.
Falls nein, installieren Sie Homebrew wie auf
[HREF::https://brew.sh/]
beschrieben.

Im einfachsten Fall können Sie nun aus dem Kommando 
`sudo apt install xyz`
in der Aufgabe auf Ihrem Mac einfach das gleichwertige
`brew install xyz`
machen.

Manchmal heißt das Paket auf Homebrew aber nicht genau gleich.
In dem Fall können Sie mit 
`brew search passendesthemenstichwort`
nach Paketen suchen, um das richtige zu finden
oder Sie machen eine Websuche
"homebrew apt package xyz".

Die Pakete werden auf Homebrew _"formulae"_ genannt (das ist Plural. Singular: _"formula"_),
was evtl. die Websuche verbessern hilft.

Führen Sie mit diesem Wissen die obigen Schritte [EREFQ::4] und [EREFQ::5] 
in der passenden Mac-Version aus.
(Das Gegenstück zu `apt update` gibt es auch bei Homebrew: `brew update`.
Aufrufen muss man es aber meist nicht, das macht Homebrew automatisch.)
